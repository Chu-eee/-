# 四个文件的数据结构 Token 学习指南

> 目标：不是背代码，而是把代码压缩成一组可触发的概念（token）。
> 看到 `insert`、`remove`、`p != head`、`new Node` 这些词，脑子里能自动浮出对应的指针动作。

---

## 0. 先看全局：四个文件分别在干什么

| 文件 | 一句话 | 类比 |
|---|---|---|
| `Node.java` | 定义“盒子”：数据 + 指向下一个盒子的引用 | 火车车厢 |
| `SinglyList.java` | 用盒子串成一条链，提供插入、删除、查找、复制等基本动作 | 一条有车头的火车 |
| `CirSinglyList.java` | 把车尾接回程车头，形成环；重写受环影响的方法；实现 `union` | 首尾相连的环形火车 |
| `CirSinglyListTest.java` | 调用 `union`，检查结果、成环、输入不变、深拷贝 | 质检员 |

两种结构画出来只有一处差别：

```text
普通单链表：
head → [1|→] → [2|→] → [3|null]

循环单链表：
head → [1|→] → [2|→] → [3|→]
  ↑                              │
  └──────────────────────────────┘
```

记住两句话：

1. **一条链靠 `next` 引用连起来。**
2. **循环表没有 `null`，走到 `head` 就说明走完一圈。**

## 1. 粗糙的“机器学习”类比

你说的这个类比是成立的，但要注意它的边界：

| ML 里的词 | 在这里对应什么 |
|---|---|
| token | 一个概念：头结点、前驱、深拷贝、`p != head` |
| embedding / 关联 | 这个概念和哪些代码、哪些动作连在一起 |
| forward pass | 读到一行代码，先预测它要干什么 |
| loss | 预测和实际代码不一致 |
| backprop | 只回去看导致错误的那几个 token，不重读全文 |
| batch | 一次学一组方法，比如“插入三兄弟” |
| overfitting | 背下了代码，但换一道题就不会 |
| generalization | 能自己写出 `subList`、`intersection` 这类同构方法 |

**学习循环**：

```text
看到方法名 → 先猜它怎么改指针 → 读代码 → 对照 → 错了就定位到具体 token → 再猜下一个
```

不要一上来从第 1 行读到第 250 行。先按下面的顺序建立主干，再回头补细节。

## 2. 阅读顺序（按这个顺序看）

### 第 1 站：`Node.java`（10 分钟）

只看三件事：

- `data`：存元素。
- `next`：存“下一个结点在哪里”，类型是 `Node<T>`，所以它存的是**引用**，不是元素本身。
- 构造方法：`new Node<T>(data, next)` 只是把这两个值装进盒子。

自测：画出 `new Node<>(1, new Node<>(2, null))` 的结构。

```text
[1|→] → [2|null]
```

### 第 2 站：`SinglyList.java` 的遍历（15 分钟）

先只看这三段（第 31-42、67-77、117-123 行）：

```java
for (Node<T> p = this.head.next; p != null; p = p.next)
```

把它读成一句话：

> 从第一个真正存元素的结点开始，只要没走到 null，就处理当前结点，然后跳到下一个。

`head` 本身不存元素，它是**头结点/哨兵**；`head.next` 才是第 0 个元素。

### 第 3 站：`SinglyList.java` 的插入与删除（30 分钟）

先看 `insert(int i, T x)`（第 80-89 行）和 `remove(int i)`（第 97-109 行）。

这两个方法共用一个模式：**先找前驱 `front`，再改 `front.next`。**

```java
// 插入
front.next = new Node<T>(x, front.next);

// 删除
front.next = front.next.next;
```

插入的等号右边先执行：新结点的 `next` 指向原来 `front` 后面的结点；然后 `front.next` 指向新结点。画图时先画新结点，再改前驱的箭头。

删除更直接：让前驱跳过当前结点。

自测：在纸上画出 `1 → 2 → 3`，在 2 后面插 9、删掉 3，各需要改哪根箭头。

### 第 4 站：`SinglyList.java` 的查找、复制、equals（20 分钟）

- `search(key)`：遍历，找到 `key.equals(p.data)` 就返回结点。
- `copy(list)`：清空自己，遍历 `list`，每个元素 `new Node<T>(p.data, null)`，尾接。
- `equals(obj)`：两条链同时走，逐个比较 `data`，最后必须同时到 `null`。

核心 token：**深拷贝 = 每个结点都 new，不是复制引用。**

### 第 5 站：`CirSinglyList.java` 的“只改一处”（25 分钟）

先看构造方法（第 6-22 行）：

```java
this.head.next = this.head;   // 空表：头结点指向自己
rear.next = new Node<T>(values[i], this.head);   // 新结点直接指向头
```

然后看第 30-31 行的注释：**所有靠 `p != null` 找表尾的方法都要重写，改成 `p != this.head`。**

为什么？因为循环表里没有 `null`。如果你写 `p != null`，`p` 会绕着环一直走，永远不停。

对比背下面三行：

```java
// 普通表
for (Node<T> p = head.next; p != null; p = p.next)

// 循环表
for (Node<T> p = head.next; p != head; p = p.next)

// 空循环表
head.next == head
```

### 第 6 站：`union`（30-40 分钟）

先不要看代码，先看这句话：

> 结果 = this 的前 i 个结点（A） + list 的全部结点（B） + this 的剩余结点（C）。

然后把 `union` 拆成 4 个动作：

1. 建空结果表 `result`，`rear` 指向 `result.head`。
2. 复制 A：`p` 从 `this.head.next` 走，最多走 `i` 步。
3. 复制 B：`q` 从 `list.head.next` 走，走到 `null`（或 `list.head`）。
4. 复制 C：`p` 继续走完 `this` 剩下的结点。
5. 最后 `rear.next = result.head`，成环。

关键 token：

- `rear`：永远指向结果表的最后一个结点。
- `new Node<T>(x, result.head)`：新结点的 `next` 先指向结果表的头。
- `count < i`：控制 A 段长度，不调用 `size()`。
- `p != this.head`：遍历循环表。
- `q != stop`：兼容普通表和循环表。

自测：拿 `this=(1,2,3)`、`list=(4,5)`、`i=1`，在纸上一步一步画 `result` 的链，画到 `(1,4,5,2,3)` 为止。

### 第 7 站：`CirSinglyListTest.java`（15 分钟）

看它验证了什么：

- 5 种 `i`：中间、头、尾、越界、负数。
- `isCircle`：尾结点是不是回到 `head`。
- `shareNode`：结果和原表有没有共用同一个 `Node` 对象。
- 修改 `result`，原表是否不变。

这四个检查对应四个 token：**边界、成环、深拷贝、输入不变。**

## 3. 压缩 token 展开表

这一节是你最想要的“把压缩概念还原”的部分。

### 3.1 单链表的遍历

| 项 | 内容 |
|---|---|
| 触发词 | `for (Node<T> p = ...; p != null; p = p.next)` |
| 关键动作 | `p` 从 `head.next` 开始，每次 `p = p.next` |
| 终止条件 | 普通表 `p == null`；循环表 `p == head` |
| 边界 | 空表时 `head.next == null`（普通）或 `== head`（循环） |
| 一句话 | 遍历就是让一个引用沿着 `next` 走，直到碰到结束标志 |

### 3.2 单链表的插入

| 项 | 内容 |
|---|---|
| 触发词 | `insert(int i, T x)` |
| 关键动作 | 先找第 `i-1` 个结点 `front`，再执行 `front.next = new Node<>(x, front.next)` |
| 边界 | `i < 0` 头插；`i >= 长度` 尾插（循环表同样容错） |
| 一句话 | 插入 = 新结点接管 `front` 原来的后继，`front` 再指向新结点 |

### 3.3 单链表的删除

| 项 | 内容 |
|---|---|
| 触发词 | `remove(int i)` / `remove(T key)` |
| 关键动作 | 找前驱 `front`，执行 `front.next = front.next.next` |
| 边界 | `i` 越界返回 `null`；循环表要判断 `front.next == head` |
| 一句话 | 删除 = 让前驱跳过当前结点，当前结点没人引用后被回收 |

### 3.4 单链表的复制（深拷贝）

| 项 | 内容 |
|---|---|
| 触发词 | `copy(SinglyList<T> list)` / 拷贝构造方法 |
| 关键动作 | 清空自己 → 遍历原表 → 每个元素 `new Node<T>(p.data, ...)` → 尾接 |
| 边界 | 原表为空时，结果表只有头结点 |
| 一句话 | 深拷贝复制的是“结点”，不是“元素对象”；新表和原表不共用任何 `Node` |

### 3.5 单链表的查找

| 项 | 内容 |
|---|---|
| 触发词 | `search(T key)` |
| 关键动作 | 遍历，`key.equals(p.data)` 成立就返回当前结点 |
| 边界 | 找不到返回 `null` |
| 一句话 | 查找 = 遍历 + 一个相等判断 |

### 3.6 循环单链表的改写

| 项 | 内容 |
|---|---|
| 触发词 | `p != null`、`clear()`、`isEmpty()` |
| 关键动作 | 把结束标志从 `null` 换成 `this.head`；`clear()` 把 `head.next` 指回 `head` |
| 边界 | 空表 `head.next == head`；尾结点 `next == head` |
| 一句话 | 循环表不是新发明，只是把链尾的 `null` 换成了 `head` |

### 3.7 单链表的并集

| 项 | 内容 |
|---|---|
| 触发词 | `union(int i, SinglyList<T> list)` |
| 关键动作 | 建 `result` → 复制 A → 复制 B → 复制 C → `rear.next = result.head` |
| 边界 | `i < 0` 当 0；`i > 长度` 当长度；`this` 或 `list` 为空 |
| 一句话 | 并集 = 在副本的第 `i` 个位置前插入 `list` 的副本，重复元素保留 |

## 4. Token 总表

### 4.1 Java 底座 token（你有基础，快速过）

| Token | 一句话 | 在代码里 |
|---|---|---|
| 引用 | 变量存的是对象地址，不是对象本身 | `Node<T> next`、`head` |
| `new` | 在堆上创建一个新对象 | `new Node<T>(...)` |
| 泛型 `T` | 元素类型由使用者决定 | `Node<T>`、`SinglyList<T>` |
| 构造方法 | 创建对象时初始化字段 | `public Node(...)` |
| 重载 | 同名方法，参数不同 | `insert(int,T)` / `insert(T)` |
| 继承 | 子类拥有父类的字段和方法 | `CirSinglyList extends SinglyList` |
| 覆盖 | 子类重写父类方法 | `@Override` |
| `instanceof` | 判断运行时类型 | `list instanceof CirSinglyList<?>` |
| `null` | 没有指向任何对象 | 普通表的结束标志 |
| `this` | 当前对象 | `this.head`、`this.clear()` |

### 4.2 结点与链 token

| Token | 一句话 | 在代码里 |
|---|---|---|
| 结点 `Node` | 数据 + 后继引用 | `Node.java` |
| 数据域 `data` | 存元素 | `p.data` |
| 地址域 `next` | 存下一个结点的引用 | `p.next` |
| 头结点 `head` | 不存元素的哨兵结点 | `this.head` |
| 首结点 | 第一个真正存元素的结点 | `head.next` |
| 尾结点 | 最后一个结点 | 普通表 `next == null`；循环表 `next == head` |
| 前驱 `front` | 当前结点前面的那个结点 | `insert`、`remove` |
| 空表 | 只有头结点 | 普通 `head.next == null`；循环 `head.next == head` |
| 链 | 靠 `next` 串起来的一串结点 | 整条表 |

### 4.3 普通单链表动作 token

| Token | 一句话 | 代码位置 |
|---|---|---|
| 遍历 | 沿 `next` 走完整条表 | 第 39、70、119 行 |
| 尾插 | 走到尾结点后接新结点 | 第 12-22、91-94 行 |
| 头插 | 在 `head` 后插入 | `insert(i<0)` |
| 按位插入 | 找前驱，改 `front.next` | 第 80-89 行 |
| 按位删除 | 找前驱，跳过当前结点 | 第 97-109 行 |
| 按值删除 | 查找 + 删除 | 第 125-140 行 |
| 查找 | 遍历 + `equals` | 第 117-123 行 |
| 判空 | `head.next == null` | 第 31-34 行 |
| 长度 | 遍历计数 | 第 36-42 行 |
| `get/set` | 走到第 `i` 个结点后取/改 `data` | 第 44-65 行 |
| `toString` | 遍历拼字符串 | 第 67-77 行 |
| 深拷贝 | 每个结点都新建 | 第 143-152 行 |
| `equals` | 两条链同步走，逐结点比较 | 第 155-173 行 |

### 4.4 循环单链表 token

| Token | 一句话 | 代码位置 |
|---|---|---|
| 环 | 尾结点的 `next` 指回 `head` | 第 9、19 行 |
| 空表自环 | `head.next == head` | 第 36 行 |
| 终止条件 | `p != this.head` | 第 43、79、131 行等 |
| 重写 | 父类用 `null` 判断的方法都要覆盖 | 第 33-208 行 |
| `clear` 差异 | `head.next = head`，不是 `null` | 第 122-126 行 |
| `copy` 兼容 | 判断 `list` 是普通表还是循环表 | 第 156-169 行 |
| `equals` 兼容 | 普通表对 `null`，循环表对 `head` | 第 172-208 行 |

### 4.5 `union` token

| Token | 一句话 | 代码位置 |
|---|---|---|
| 并集 = 拼接 | 不是数学去重，重复元素保留 | 第 210-249 行 |
| A 段 | `this` 的前 `i` 个结点 | 第 218-227 行 |
| B 段 | `list` 的全部结点 | 第 229-236 行 |
| C 段 | `this` 的剩余结点 | 第 238-244 行 |
| `rear` | 始终指向结果表尾 | 第 216 行起 |
| `result.head` | 每个新结点先指向它 | 第 223、234、241 行 |
| 一次遍历 | 不先求长度 | 全程 |
| `i` 容错 | `count < i` 自然处理负数/越界 | 第 221 行 |
| 深拷贝 | 结果不与输入共用结点 | 第 223、234、241 行 |
| `list` 类型判断 | 兼容普通表和循环表 | 第 231-232 行 |

### 4.6 复杂度与测试 token

| Token | 一句话 |
|---|---|
| `O(1)` | `isEmpty`、`clear` 这类不随长度增长的操作用 |
| `O(n)` | 遍历、查找、按位插入/删除 |
| `O(n+m)` | `union` 的时间与空间 |
| 不调用 `size()` | 用 `count` 边走边数 |
| 输入不变 | 只读 `p.data`，不改 `this/list` 的 `next` |
| 成环检查 | 尾结点是不是 `== head` |
| 共用结点检查 | 两个表里有没有同一个 `Node` 对象 |

## 6. 老师可能问的 15 个问题（一句话答案）

| 问题 | 一句话答案 |
|---|---|
| `head` 和 `head.next` 有什么区别？ | `head` 是哨兵，不存元素；`head.next` 是第一个真正存元素的结点。 |
| 为什么单链表要带头结点？ | 让头插、删除、遍历的代码统一，不用单独处理“第一个结点”。 |
| `next` 存的是什么？ | 存下一个 `Node` 对象的引用。 |
| 普通表怎么判断走完？ | `p == null`。 |
| 循环表怎么判断走完？ | `p == head`。 |
| 循环表为什么不能用 `p != null`？ | 环里永远没有 `null`，会死循环。 |
| `insert` 的关键一句话？ | 新结点接管前驱原来的后继，前驱再指向新结点。 |
| `remove` 的关键一句话？ | 让前驱跳过当前结点。 |
| 深拷贝复制了什么？ | 每个 `Node` 都是新的；`data` 引用可以共享。 |
| `union` 为什么叫并集却不是去重？ | 教材里的“集合并”是拼接，重复元素保留。 |
| `union` 的时间复杂度？ | `O(n+m)`，`this` 和 `list` 各遍历一次。 |
| 空间复杂度？ | `O(n+m)`，要新建 `n+m` 个结点。 |
| 为什么不先 `size()`？ | 题目要求一次遍历；用 `count` 边走边数即可。 |
| `i` 越界怎么办？ | `i<0` 头插，`i>=长度` 尾插，`count < i` 自然实现。 |
| 怎么验证结果正确？ | 看次序、看成环、看 `this/list` 是否不变、看有没有共用结点。 |

## 7. 五个最容易挂的点

1. **`head` 是哑结点。** 它不存元素。第 0 个元素在 `head.next`。
2. **插入/删除都在改 `front.next`。** 先找前驱，再改箭头。画图时先画新箭头，再断旧箭头。
3. **循环表的结束标志是 `head`，不是 `null`。** 这是整章最容易死循环的地方。
4. **深拷贝 = 每个结点 `new`。** 只复制头结点、共享后面结点的，是浅拷贝。
5. **`union` 是 A+B+C + `rear` + 成环。** 不要一上来写循环，先在纸上画三段。
